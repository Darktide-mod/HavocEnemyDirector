# 浩劫敵人導演

為 SoloPlay 和 Realms 建立具名編隊，讓不同投放規則擁有獨立時機，並透過可選的自適應導演調節壓力。HED 同時保留原版敵人模板精調，可以按需跟隨 HCM 的整體倍率。

## DIY 詞條與天賦聯動

Havoc Condition Manager 的 DIY 詞條和死靈 DIY 天賦可請求已有的具名編隊或允許生成的敵人型別。請求進入導演原有的排程與刷怪流程，遵守當前容量、落點、階段和節奏條件。請求成功表示已入隊，不保證所有請求敵人都能生成。

部署編輯器與原生模板規則支援檢查生效詞條 ID 和具名訊號。複製 ID 後點選條件數值貼上。DIY 暫停動作可同時阻止 HED 接納新刷怪任務與繼續生成佇列成員，完成、過期及任務清理會釋放佇列狀態。單次請求、併發狀態及全域性請求次數均有限制，約束連續增援鏈。

docs/diy 包含介面說明、可編輯 JSON 示例與三語手冊。對應聯動需要當前 HCM 和死靈 DIY 版本；HCM 仍是 HED 的必要依賴。普通 DIY 敵人透過共用生成路徑保留獨立來源標記，特感與怪物保留各自原生註冊流程。

## 開始使用

從模組選項開啟 Havoc Enemy Director，或進入本地遊戲設定的“詳細調節”頁。介面分為“導演總覽”“編隊庫”“投放規則”“原版模板”“方案與變更”五個區域。

- 建立編隊，選擇敵人類別、成員兵種和人數範圍。
- 建立呼叫該編隊的投放規則，選擇經過時間、向前推進或條件轉為滿足時觸發。
- 設定首次到場時間、附加條件和整局額度，準備好後啟用額外編隊導演。

額外導演預設關閉，原版模板編輯可獨立使用。設定自動儲存，下一局生效；當前任務保留開局配置。

點選數字可輸入或貼上，回車或點選外部確認，Esc 取消；長按加減可連續調整。點選編隊或規則名稱即可重新命名，最多 48 個字元。較長列表可滾動，下拉選單隻標記當前選中項。

## 編隊庫

最多儲存 32 個編隊與 64 條投放規則，同一類別可以建立多個獨立編隊，支援屍潮敵群、小股敵群、特感、怪物及巡邏編隊。每個編隊最多八個帶權變體，每個變體最多十六種成員。一次遭遇抽取一個變體；成員的上下限表示人數，變體權重表示抽取傾向。

同一編隊可被多條規則呼叫。複製編隊或規則會建立獨立物件，投放規則副本擁有獨立隨機流。仍被投放規則引用的編隊不能直接刪除，需要先移除對應規則。

每個變體在執行時縮放前最多配置 300 名普通敵人、16 名特感或 3 只怪物。怪物編隊支援瘟疫歐格林、納垢獸與混沌魔物；任務角色和劇情 Boss 不在此編隊庫中開放。

## 投放規則

每條規則獨立儲存首次到場時間、再次投放間隔、冷卻、整局額度和同時活躍遭遇上限。多條規則呼叫同一編隊，也不會共用這些計數。

- 時間觸發：指定最短、最長間隔；再次投放的間隔從首名成員被接納後開始計算。
- 推進觸發：指定首次主路徑距離及下一次所需繼續推進距離；一次跨過多個門檻不會積壓補發。
- 條件觸發：條件由不滿足變為滿足時執行一次；持續滿足不會反覆觸發，須先變為不滿足才能重新觸發。
- 可進一步設定有效時間視窗、一次遭遇的波數及波間等待。

每組最多八項條件，可要求全部滿足或任意一項滿足。條件包括有效玩家、戰鬥負擔、原版節奏、怪物、任務事件、原版屍潮生成、協同狀態和推進情況。預設只限制遭遇開始，也可選擇在首名成員到場後繼續檢查，避免第一隻怪物出現就使同編隊的後續成員被自己的條件卡住。

整局額度統計至少已有一名成員被接納的遭遇；0 表示該規則不限次數。等待生成和仍有存活成員的遭遇都會佔用活躍額度。遭遇次數、成員人數及波數分別計算。

多條規則同時符合要求時，可以先比較優先順序再按權重抽取，也可直接按權重抽取。高優先順序可能讓低優先順序規則持續等待。要求某個 HED 階段的規則需要自適應模式。

## 自適應壓力與到場限制

規則模式按已配置規則執行。自適應模式經歷蓄壓、施壓、恢復，各階段具有獨立時長範圍、人數倍率及頻率倍率。戰鬥負擔過高或有效玩家過少時可提前進入恢復；恢復須同時達到規定時長與低負擔條件才結束。階段頻率設為 0 會暫停 HED 的新增提交。

導演控制額外編隊，原版節奏和任務指令碼繼續執行。全域性設定控制兩次接納間隔、活躍遭遇上限、最低有效玩家數、戰鬥負擔門檻，以及是否允許在任務事件期間額外投放。

普通成員分批使用原版生成與敵群管理；巡邏沿用原版巡邏行為，特感佔用可用的原版槽位，怪物使用原版登記流程。普通敵人與怪物透過 HCM 檢查出生距離、遮擋和實際可達性；特感沿用原版選點與保護機制，可能延後到場或被替換。

每次 HED 遭遇的所有波次合計最多 256 名普通敵人、16 名特感或 3 只怪物。縮放後超過額度時，按成員比例縮減；波數也受遭遇總額度限制。等待中的編隊輪流提交，過期請求取消，不積壓成連續補發。已被原版槽位接納的特感繼續執行原版流程。HED 自定義普通編隊不進入 HCM 的自動回收補投池，以保留獨立活躍額度；原版敵群仍使用 HCM 回收。

## HCM 聯動與原版模板

投放規則可跟隨 HCM 的人數和頻率，再乘自己的倍率。普通屍潮、小股成員跟隨對應人數控制，精英跟隨“敵群精英人數”；特感跟隨並行容量，怪物跟隨遭遇數，巡邏普通成員從一倍開始。屍潮、小股潮、特感的再次間隔跟隨對應頻率，其他類別從一倍開始。首次時間、最短冷卻及明確配置的波次仍使用本規則的數值。

原版模板包括戰鬥節奏與熱度、駐軍、屍潮、特感、怪物、自動事件、詞條機制和受支援的任務戰鬥節點。依次選擇來源、模式與分支，可切換常用引數、全部欄位、已修改欄位。抗性分檔與挑戰分檔分別標註，不等同於浩劫等級。

數值欄位可選擇跟隨 HCM、使用固定值，或在 HCM 結果上乘倍率。原版值、HCM 後的值和 HED 模板結果分別顯示；機率按百分比輸入，詳情可展開原版標識。

原版遭遇條件預設追加到現有檢查上，只有支援的協同屍潮條件列表允許替換。選擇一個模板不會自動啟用該刷怪來源。任務目標及不支援的函式欄位繼續由原版控制。舊的“同時活躍屍潮上限”欄位已從常用引數中排除，因為核對的原始碼未確認其實際讀取位置。

難度、已選詞條及執行時修正仍可能影響模板效果。任務事件點數不是敵人人數；HCM 事件預算倍率還會作用於原版最終預算與封頂。

## 隨機種子

導演種子與駐軍佈局種子分別提供「固定種子」開關。關閉時沿用任務種子，開啟後可輸入 1–2147483646 的整數，關閉會保留輸入值。每條投放按穩定身份分別使用計時、變體、成員人數隨機流，不重新設定遊戲全域性隨機數。

相同種子與相同輸入可復現 HED 的選擇。玩家移動、原版隨機、規則競爭和可用出生點仍會影響實際戰鬥。佈局種子用於駐軍佈置，不負責選擇任務地圖，也不會統一所有原版系統的隨機性。

## 方案

方案儲存 HCM 數值、原版固定值與相對倍率、原版條件、編隊、投放規則、導演設定、兩類 HED 種子的開關與數值，以及 HCM 詞條事件種子；缺少 HCM 種子的舊方案保留當前該項設定。任務、詞條、陣營和環境選擇仍由 SoloPlay 儲存。

資料夾：%APPDATA%/Fatshark/Darktide/HavocEnemyDirector/templates

- 名稱最多 64 個字元；覆蓋已有檔案需要確認。
- 選擇檔案、檢視摘要，再載入為下一局配置。
- 分享 JSON 檔案或複製分享內容。可從剪貼簿匯入，也可放入資料夾後重新整理；匯入不會自動載入。
- 刪除檔案需要確認，也不會重置當前已載入配置。

檔案上限 256 KiB。上一版原版模板方案會遷移，無法相容的早期生成器方案仍留在磁碟上。無效欄位和不適配的成員會被拒絕；方案只儲存資料，不執行 Lua。

方案庫的全部重置會清除 HED 設定、編隊、規則和兩類種子，保留 HCM 數值與方案檔案。導演摘要另有僅清除原版覆蓋的按鈕，兩種重置均需再次點選確認。

## 使用前提與相容性

需要 Darktide Mod Loader、Darktide Mod Framework、SoloPlay，以及具備共享尋路支援的當前 Havoc Condition Manager。Realms 為可選的玩家主機聯機依賴。遊戲改動由本地主機執行，英文、簡體中文和繁體中文隨遊戲語言切換。

請使用相容的配套版本，安裝後重新啟動遊戲。其他替換相同原版模板或排程方法的模組可能衝突。關閉 HED 後，HCM 可以獨立執行。

## Vortex 安裝

- 關閉遊戲並安裝前置。使用 Install From File 匯入本 ZIP，啟用後選擇 Deploy Mods。
- Load Order 順序：SoloPlay → HavocConditionManager → HavocEnemyDirector。
- 重新啟動遊戲，從模組選項開啟 Havoc Enemy Director。

## 手動安裝

- 關閉遊戲。升級時先移除舊 HavocEnemyDirector 安裝資料夾，再解壓新包；設定與方案存放在其他位置。
- 解壓到 Darktide/mods，得到 mods/HavocEnemyDirector。
- 在 mods/mod_load_order.txt 中將 HavocEnemyDirector 排在 HavocConditionManager 後，SoloPlay 位於兩者之前。
- 重新啟動遊戲，從模組選項開啟 Havoc Enemy Director。
